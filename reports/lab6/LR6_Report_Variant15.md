## 3. Детальное описание и примеры работы модулей

### 3.1. Модуль параметризованных запросов и безопасного доступа к данным
Подключение к базе данных осуществляется исключительно с использованием параметризованных подготовленных выражений (`Prepared Statements`), что исключает риск внедрения вредоносного SQL-кода:

```python
# Пример безопасного выполнения параметризованного запроса:
def get_semester_disciplines(curriculum_id: int, semester_num: int):
    conn = get_db()
    try:
        query = """
            SELECT cd.*, d.short_name AS dept_short
            FROM curriculum_disciplines cd
            LEFT JOIN departments d ON d.id = cd.implementing_department_id
            WHERE cd.curriculum_id = ? AND cd.semester_num = ?
            ORDER BY cd.id
        """
        return conn.execute(query, (curriculum_id, semester_num)).fetchall()
    finally:
        conn.close()
```

### 3.2. Модуль автоматизированной валидации по ФГОС ВО 3++
Модуль выполняет проверку соответствия параметров загруженного проекта УП нормативной базе стандарта. Все показатели вычисляются непосредственно из базы данных (функция `validate_curriculum`):

1. **Баланс зачетных единиц:** $\\sum \\text{credits} = 240\\text{ з.е.}$ (по 30 з.е. в каждом семестре 1–8).
2. **Экзаменационная нагрузка:** $\\text{count}(\\text{Exams}) \\le 5$ в каждой промежуточной сессии (фактический максимум — 4 экзамена).
3. **Объем практической подготовки:** $\\sum \\text{credits}(\\text{Блок 2}) \\ge 12\\text{ з.е.}$ (фактически 34 з.е. — учебная, технологическая, производственная и преддипломная практики).
4. **Объем государственной итоговой аттестации:** $\\sum \\text{credits}(\\text{Блок 3}) \\ge 6\\text{ з.е.}$ (фактически 9 з.е. — государственный экзамен и защита ВКР).

### 3.3. Модуль бизнес-аналитики и визуализации данных (Chart.js)
На страницу `?page=analytics` подключен готовый компонент **Chart.js 4**. Серверная часть формирует данные из таблиц `curriculum_disciplines` и `competencies` и передает их в три интерактивные диаграммы:

1. **Круговая диаграмма (Doughnut)** — структура блоков учебного плана: обязательная часть 117 з.е., вариативная часть 71 з.е., практики и НИР 34 з.е., ГИА 9 з.е., ФТД 9 з.е.
2. **Радарная диаграмма (Radar)** — баланс формирования компетенций по категориям УК / ОПК / ПК.
3. **Накопительная столбчатая диаграмма (Stacked Bar)** — распределение академических часов по 8 семестрам с разделением на лекции, лабораторные, практики и СРС (контрольный итог 1080 ч. на семестр).

## 4. Особенности интеграции и безопасности

1. **Разделение ответственности:** все данные для модулей (метрики, события, диффи, составы подписей) вычисляются сервером из базы данных и передаются клиентским библиотекам в виде JSON — модули не обращаются к СУБД напрямую.
2. **Устойчивость к оффлайн-режиму:** страницы портала рендерятся сервером, поэтому при недоступности CDN интерфейс сохраняет работоспособность (таблицы и данные отображаются, интерактивные диаграммы деградируют до статических контейнеров).
3. **Безопасность:** параметризованные запросы исключают SQL-инъекции; вывод экранируется (`htmlspecialchars` / `html.escape`) — защита от XSS; все значимые действия протоколируются в журнале аудита с фиксацией IP-адреса и роли пользователя.
4. **Лицензирование:** все подключенные модули распространяются под открытыми лицензиями (MIT, Apache-2.0, BSD) и бесплатны для учебного использования.
